# Put a public demo online (GitHub and Render)

About 15 minutes, on Render's free plan. The code lives on GitHub; Render builds it, runs it and gives it an HTTPS address. Everything Render needs is in [`render.yaml`](../render.yaml).

## 1. Put the code on GitHub

1. Unzip `ruffbus-mamer.zip` (Windows: right-click > *Extract All*).
2. On [github.com](https://github.com), click **+** (top right) > **New repository**.
   - Name: `ruffbus-mamer-demo`.
   - *Public* lets anyone read the code; *Private* keeps it to you. Render can deploy either.
   - Leave *Add a README* unticked. Click **Create repository**.
3. On the empty repository page, click the link **uploading an existing file**.
4. In File Explorer, open the `ruffbus-mamer` folder, press **Ctrl+A** and drag everything *inside* it onto the GitHub page. Don't drag the folder itself: `render.yaml` and `Dockerfile` must end up at the top level of the repository.
5. When the files are listed (58 of them), click **Commit changes**.

Check: the repository's front page shows the README with screenshots, and `render.yaml` is in the file list.

If you use git instead: `git init`, `git add .`, `git commit -m "First version"`, then push to the new repository.

## 2. Deploy on Render

1. Go to [render.com](https://render.com) > **Get Started** and sign up with your GitHub account.
2. In the Render dashboard, click **New** > **Blueprint**.
3. Connect GitHub if asked and give Render access to `ruffbus-mamer-demo`. Select the repository and give the Blueprint a name, such as `ruffbus-demo`.
4. Render reads `render.yaml` and lists two free resources in Frankfurt: the web service `ruffbus-mamer-demo` and the database `ruffbus-demo-db`. Click **Deploy Blueprint** (or **Apply**).
5. Wait a few minutes. Open the web service > **Logs**: the first start is done when you see `loaded demo accounts and sample rides`, and the service shows **Live**.

If Render asks for a card: that's an anti-abuse check. Nothing here is charged as long as `render.yaml` says `plan: free`, which it does.

## 3. Try it

- The address is at the top of the web service page, for example `https://ruffbus-mamer-demo.onrender.com` (Render adds a few characters if that name is taken).
- Book a ride with any mobile number: in demo mode the code appears on screen.
- Open `/staff` and sign in as `dispatch` / `ruffbus-dispatch` to see the request arrive. The other demo accounts are in the README.

## What the Blueprint sets up

| Setting | Why |
|---|---|
| Free plan, Frankfurt region | No cost; data stays in the EU |
| `SECRET_KEY` generated by Render | Never written in the repository |
| `COOKIE_SECURE=true` | Render serves the site over HTTPS |
| `DEMO_DAILY_RESET=true` | Everything visitors enter is wiped and the sample fortnight reloaded once a day |
| `FORWARDED_ALLOW_IPS=*` | The app sees each visitor's address through Render's proxy (rate limits) |
| Database `ipAllowList: []` | The database accepts no connections from the internet, only from the app |

## Good to know

- **It sleeps.** After 15 minutes without visitors Render stops the app. The next visit wakes it in about a minute; the first visit of a new day takes a little longer because the demo reloads. Open the site yourself a couple of minutes before showing it.
- **Changes deploy themselves.** Edit or re-upload a file on GitHub and commit: Render rebuilds and redeploys within a few minutes.
- **The free database expires** 30 days after it is created, with a 14-day grace period. To continue for free: in Render, delete the web service, the database and the Blueprint, then do step 2 again. The app loads fresh demo data on its own. Or upgrade the database to a paid plan.
- **Taking it down:** delete the web service, the database and the Blueprint in Render, and make the GitHub repository private or delete it.
- **Before sharing widely:** the banner says it is a prototype, not the commune's service, and asks visitors not to enter real personal details. Keep it, and consider telling the commune first.
